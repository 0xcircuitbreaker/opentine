# 0.77 batched streaming ingest: recorded results

`scripts/bench/ingest_stream.py`, batches of 10,000 synthetic RL step events
(about 70 bytes each), every batch signed (Ed25519) and chained, one
durability point per batch. Raw numbers: `0.77-ingest.json`.

Hardware: 4 vCPU x86_64 VM, Linux 6.18.44-fc-v726, Python 3.13.18
(a shared development container, not the reference machine).

## Against the acceptance target

* **10,000 events/s sustained, signed batches:** met here without the
  credential scrubber (about 22,000 events/s direct and over the loopback
  endpoint); with `redact: true` this machine reaches about 6,200 events/s,
  the scrubber being the cost. Rate below 1 is faster, since only captured
  events are encoded and stored.
* **1 hour and 1e8 events:** not run here (about 2 GB of free disk; 1e8
  events is several GB). Runs were 15-90 s and up to 2,000,000 events; batch
  latency stayed flat across the run (p99 within 20% of p50), so the rate is
  not expected to decay with chain length. The full runs are owner-run:
  `--events 100000000` and `--seconds 3600` on the reference machine.
* **Batch commit latency** (the time until a batch is durable and the head
  has moved) was under 0.6 s at 10,000 events per batch without the scrubber.
* `tine ingest verify` reads the chain twice (ids back, checks forward):
  about 40 s per million stored events here.
