# 0.84 RL-scale capture: recorded results

`scripts/bench/rl_capture.py --episodes 1000000 --segment 100000 --batch 10000`.
The bench generates synthetic RL episodes (one JSON line each, about 200
bytes) and runs them end to end:

* **Ingest:** batches of 10,000 under a `rate = 1`, `redact: false` signed
  policy, each batch signed and chained (0.77).
* **Seal:** every 100,000 episodes, one Merkle-rooted segment, committed in
  the op log and signed by a pinned runner key.
* **Audit:** one audit per segment for "99% confidence that at most 0.5% are
  tampered or missing", signed by a pinned auditor key.

`tine ingest segments` then re-derives every segment and audit. The raw
numbers are in `0.84-rl-capture.json`.

Hardware: 4 vCPU x86_64 VM, Linux 6.18.44-fc-v880, CPython 3.13.18. This is
a shared development container, not the reference machine.

## Against the acceptance target

* **1M synthetic episodes per hour:** met on this machine by about 21x end to
  end. Ingest, seal and audit together took 167 s for 1M episodes.
* **Seal** re-reads the segment's batches to build the leaves and the tree.
  This costs about 0.6 s per 10,000 episodes here.
* **Audit** rebuilds the tree to prove each sampled episode. It costs about
  3.8 s per 100,000-episode segment, and the 913 samples themselves are a
  small part of that.
* **`tine ingest segments`** re-derives every root and re-runs every
  repository-source audit, so it costs about the same as seal plus audit.
* Tests never assert any of these times. The acceptance fixture
  (tests/test_084_rl_acceptance.py) asserts detection counts only.
