# Live tail latency (0.77)

Commands:

    python scripts/bench/tail_latency.py --mode cli --seconds 120 --rate 200 --batch 50
    python scripts/bench/tail_latency.py --mode sse --seconds 120 --rate 200 --batch 50

These ran on a 4-core x86_64 container (Intel Xeon 2.10 GHz, 15 GB RAM,
Linux 6.18) with Python 3.13.18. The raw numbers are in
docs/bench/0.77-tail.json.

Latency is measured from the moment the writer's ref move returned (the
event is durable) to the moment the follower yielded the row. `cli` is the
`tine log -f` engine polling every 0.05 s. `sse` is `GET tail?all=1` on an
in-process `tine serve` app; there, the ref move wakes the stream.

| Path | events measured | p50 | p95 | p99 | max | all under 1 s |
| --- | --- | --- | --- | --- | --- | --- |
| `tine log -f` (cli) | 8,751 | 0.080 s | 0.117 s | 0.128 s | 0.129 s | yes |
| `GET tail` (sse) | 6,501 | 0.028 s | 0.045 s | 0.051 s | 0.057 s | yes |

The target is a tail latency under 1 s, and it is met on both paths.

## Limits of this run

- The run lasted 2 minutes, not the 1 hour the plan names.
- The run was writer-bound: one writer thread reached 74 events/s (cli) and
  55 events/s (sse), below the requested 200. The tail kept up with every
  event the writer produced. Sustained ingest at 10,000 events/s is the
  streaming ingest path's own bench, not this one. To repeat this bench at
  that rate on the reference machine, use `--rate 10000 --seconds 3600`.
- In `cli` mode, latency includes up to one poll interval (`--interval`).
  `tine log -f` defaults to 0.2 s.
