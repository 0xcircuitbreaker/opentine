# Transcript analysis at 100,000 transcripts (0.74)

Command: `python scripts/bench/transcripts.py --transcripts 100000 --cluster
10000 --k 16 --out docs/bench/0.74-transcripts.json` on a 4-core x86_64
container (Intel Xeon @ 2.10GHz), Python 3.13, standard library only (numpy
present but unused by these paths). Raw numbers: docs/bench/0.74-transcripts.json.

Acceptance target (plan 0.74): 100k transcripts indexed in under 30 minutes on
an 8-core reference CPU, hardware recorded with the result. This run used 4
cores and a single process.

Corpus: 100,000 synthetic transcripts from the seeded generator
(`scripts/gen_transcript_corpus.py`, seed 75), 39 MB of text, about 15% with a
seeded behaviour. Backend `opentine.tfidf-hash/1`, digest
`sha256:19cde5ad...eb66` (with the 0.74 review's text normalisation:
NFKC, format characters dropped, lookalikes mapped, base64 decoded).

| Part | Size | Seconds |
| --- | --- | --- |
| Index: fit the space (features, IDF, vectors, mean) | 100,000 transcripts | 20.7 |
| One "runs like these" query (5 exemplars, top 50) | 100,000 transcripts | 7.9 |
| Seeded k-means, k = 16, 23 rounds to converge | 10,000 transcripts | 17.9 |

Indexing 100,000 transcripts takes 16 s, well under the 30-minute target.
Precision@50 of a 5-exemplar query is 1.0 for each of the three seeded
behaviours (recall@50 is not meaningful here: each behaviour has about 5,000
seeded transcripts and the top 50 can hold only 50).

Not measured here: reading run text out of a repository (the search index's
extraction, docs/bench/0.65-query.md) and k-means over all 100,000 runs, which
in pure Python grows with `n x k x rounds` (minutes at this size for small `k`).
No test asserts a duration.
